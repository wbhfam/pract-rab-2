# Сравнение с pip

## Условия

Сравнение действительно выполнено локально, без интернета. Эталон — pip
24.2, Python 3.13.15, Linux x86_64. Источник метаданных приложения —
`examples/pypi`, обслуживаемый стандартным HTTP-сервером.
Снимки прочитаны из METADATA пакетов, установленных в среде выполнения.
Публичный PyPI недоступен, поэтому наличие этих версий в публичном PyPI
и актуальность снимков не проверялись.

Для эталонного запуска установленные дистрибутивы были локально упакованы
в wheel: сохранены их файлы и METADATA, пересчитан RECORD. Это локальные
перепакованные дистрибутивы, не оригинальные скачанные wheel.
Архивы, бинарные файлы пакетов и установленное окружение в git не включены.
Pip применялся **только отдельно для сравнения**, приложение его не вызывает.

Для каждого пакета эталон запускался в отдельный пустой каталог:

```sh
python3 -m pip install --no-index --find-links WHEELHOUSE \
  --no-compile --disable-pip-version-check --no-cache-dir \
  --target TARGET PACKAGE==VERSION
python3 -m pip inspect --path TARGET
```

`WHEELHOUSE` — внешний каталог локальных wheel, `TARGET` — новый каталог,
`PACKAGE==VERSION` — одна из трёх строк таблиц ниже.

## Этап 4: порядок

В таблице приведена фактическая строка `Installing collected packages`
из отдельного эталонного запуска. Дефисы и подчёркивания нормализованы
только в пояснениях, не в файлах исходного вывода pip.

| Корень | DFS postorder приложения | pip |
| --- | --- | --- |
| requests==2.34.2 | charset-normalizer, idna, urllib3, certifi, requests | urllib3, idna, charset_normalizer, certifi, requests |
| python-dateutil==3.0.0 | six, tzdata, python-dateutil | tzdata, six, python-dateutil |
| packaging==26.3 | packaging | packaging |

Результаты приложения с точными версиями: `stage4-requests.txt`,
`stage4-python-dateutil.txt`, `stage4-packaging.txt`.
Эталонные сообщения: `pip-requests.txt`, `pip-python-dateutil.txt`,
`pip-packaging.txt`.

В обоих порядках каждая зависимость предшествует своему родительскому пакету.
Порядок независимых зависимостей не единственен. Приложение использует
порядок Requires-Dist и DFS; pip использует собственный порядок установки.
Поэтому строки не обязаны полностью совпадать. Загрузка файлов по сети
и топологический порядок установки — разные операции; сравнивается именно
вторая, поскольку именно её определяет граф зависимостей.

## Тестовые случаи этапа 4

- `diamond.toml`: D, B, C, A.
- `isolated.toml`: A.
- `cycle.toml`: ошибка `Цикл: A -> B -> C -> A`, код 1.
- `self.toml`: ошибка `Цикл: A -> A`, код 1.

Для цикла топологического порядка не существует. Вместо произвольного
порядка приложение сообщает об ошибке; граф этапа 3 цикл сохраняет.

## Этап 5: визуализация и состав графа

Фактический вывод приложения (DOT и ASCII) сохранён в файлах:

- `visualization-requests.txt`;
- `visualization-python-dateutil.txt`;
- `visualization-packaging.txt`.

У pip 24.2 нет штатной команды, рисующей дерево зависимостей или граф DOT.
Поэтому несуществующий «pip tree» не используется. Для сравнения состава
графа применён штатный `pip inspect --path TARGET`: из его фактического
вывода сохранены поля name, version, requires_dist в файлах
`pip-inspect-requests.json`, `pip-inspect-python-dateutil.json`,
`pip-inspect-packaging.json`. Это сокращение вывода, не полный отчёт inspect.

| Корень | Узлы | Рёбра приложения | Результат сравнения |
| --- | --- | --- | --- |
| requests==2.34.2 | 5 | requests → charset-normalizer, idna, urllib3, certifi | Имена, версии и обязательные зависимости совпали |
| python-dateutil==3.0.0 | 3 | python-dateutil → six, tzdata | Имена, версии и обязательные зависимости совпали |
| packaging==26.3 | 1 | нет | Одиночный пакет в обоих результатах |

`pip inspect` хранит также условные Requires-Dist для незапрошенных extras.
Они не означают наличие установленных зависимостей. В граф приложения
включены только активные зависимости текущего окружения; optional extras
без запроса не включены. В частности, необязательные зависимости requests
не являются расхождением графа обязательных зависимостей.

Проверка состава графа проведена для одинаковых локальных метаданных.
Для произвольного публичного репозитория совпадение с решателем pip
не гарантируется: приложение строит граф ограничений отдельных рёбер,
а pip дополнительно разрешает глобальные конфликты версий и выбирает
дистрибутивы по платформе. Это объясняет возможные расхождения, но
не выдаётся за фактическое расхождение трёх проверенных примеров.

Таким образом, сравнение с доступными штатными средствами выполнено,
но прямое сравнение двух графических выводов pip невозможно: у pip
нет собственного графического/древовидного вывода. Сторонний pipdeptree
не использовался, чтобы не подменять штатный инструмент сторонним.
