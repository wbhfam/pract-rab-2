# Вариант 6. Граф зависимостей Python

CLI на Python 3.11+; используются только модули стандартной библиотеки.

## Настройки

Все настройки берутся только из TOML. Аргумент CLI — путь к файлу.
Все пять ключей обязательны; неизвестные ключи запрещены.

- `package`: имя пакета; в тестовом режиме — большие латинские буквы.
- `repository`: базовый URL API PyPI (`https://pypi.org/pypi`)
  или путь к тестовому файлу относительно TOML.
- `test_mode`: логическое значение TOML `true` или `false`.
- `version`: точная версия пакета (строка).
- `ascii_tree`: логическое значение, включает ASCII-дерево на этапе 5.

## Запуск и тесты

Сборка не требуется. Установка сторонних Python-библиотек не требуется.

```sh
./run.sh examples/requests.toml
python3 -B -m unittest discover -s tests -v
```

Из корня также можно запускать `python3 -B -m src examples/requests.toml`.
Ошибки выводятся в stderr; код возврата — 1, ошибка аргументов CLI — 2.

## Функции

- `config.validate_fields`: проверяет набор ключей и типы.
- `config.validate_repository`: проверяет URL или тестовый путь.
- `config.validate_http_url`: проверяет синтаксис HTTP(S) URL.
- `config.load_config`: читает TOML и проверяет имя и версию.
- `__main__.execute`: на этапе 1 печатает пять пар ключ=значение.
- `__main__.main`: разбирает путь к TOML и обрабатывает ошибки.

## Этап 1

При запуске печатаются все параметры. Ошибки всех пяти настроек,
отсутствующие/лишние ключи и неверный TOML проверяются тестами.

## Этап 2

Источником служит JSON API PyPI: `<repository>/<package>/<version>/json`.
Метаданные получает `urllib.request`, JSON разбирается `json`.
Менеджеры пакетов и сторонние библиотеки приложение не использует.
Читается `info.requires_dist`, учитываются маркеры окружения и extras.
Корневые extras не запрашиваются, поскольку такой настройки в варианте нет.
Версия корневого пакета всегда берётся из TOML, а не из latest.

### Локальная проверка без интернета

В `examples/pypi` сохранены JSON-снимки метаданных локально установленных
пакетов. Это не копия всего PyPI: для каждого пакета доступна одна версия.
Снимки сформированы из файлов METADATA установленного окружения;
их происхождение не подменяется утверждением о загрузке с публичного PyPI.

Первый терминал:

```sh
python3 -B -m http.server 8765 --bind 127.0.0.1 --directory examples
```

Второй терминал:

```sh
./run.sh examples/local-requests.toml
```

На этапе 2 вывод: `charset-normalizer`, `idna`, `urllib3`, `certifi`.
Для публичного PyPI используется `examples/requests.toml`.

### Модули метаданных

- `versions.Version`: разбор и сравнение PEP 440 версий.
- `versions.make_key`, `local_key`: нормализация частей версии.
- `versions.split_specifiers`: разбор ограничений.
- `versions.prefix_matches`, `matches_one`, `compatible`, `exclusive`,
  `satisfies`: проверка спецификаторов.
- `markers.environment`, `tokenize`, `compare`: окружение, лексер и сравнения.
- `markers.MarkerParser`: рекурсивный разбор маркеров без `eval`;
  методы `peek`, `take`, `operand`, `atom`, `conjunction`, `disjunction`,
  `evaluate` реализуют чтение и вычисление выражения.
- `markers.marker_applies`: отбор зависимостей текущего окружения и extras.
- `requirements.normalize`, `parse_requirement`, `active_requirements`:
  нормализация имени и разбор Requires-Dist.
- `repository.PyPIRepository`: кэшируемые запросы `fetch`, точные зависимости
  `dependencies`, выбор подходящей версии зависимости `select`.
- `repository.read_json`, `usable_files`: HTTP/JSON и отбор релизов.

Прямые URL-зависимости вместо имён из репозитория явно отклоняются.
Получение метаданных не устанавливает и не исполняет пакеты.

## Этап 3

`graph.build_graph` использует **DFS с рекурсией**. Узел заносится в граф
до раскрытия потомков: циклическое ребро сохраняется, повторного раскрытия
нет. Недостижимые узлы не включаются. Ограничения глубины и фильтрации
не добавлены: в варианте 6 их нет.

Тестовый файл — JSON-объект со списками смежности. Каждый узел, включая
листья, объявляется явно. Имена — большие латинские буквы.
Версия из TOML проверяется синтаксически, но не влияет на безверсионный
тестовый граф, предусмотренный заданием.

```sh
./run.sh examples/diamond.toml
./run.sh examples/cycle.toml
./run.sh examples/self.toml
./run.sh examples/isolated.toml
```

- Ромб: обход `A, B, D, C`; общее ребро `C -> D` сохраняется, Z исключён.
- Цикл: `A -> B -> C -> A`; раскрытие завершается.
- Петля: `A -> A`; раскрытие завершается.
- Изолированный пакет: только A.

### Функции графа

- `graph.validate_test_node`: проверяет имена и массивы смежности.
- `graph.TestRepository.__init__`, `dependencies`: загружают тестовый граф
  и возвращают прямые зависимости узла.
- `graph.PackageRepository.__init__`, `dependencies`: преобразуют PyPI
  в источник соседей для узлов `имя[extras]==версия`.
- `graph.build_graph`, вложенная `visit`: рекурсивно строят достижимый граф.
- `graph.analyze`: выбирает реальный/тестовый источник и корень.

Для транзитивных рёбер выбирается максимальный совместимый доступный релиз,
предпочтительно стабильный. Версии и extras входят в идентификатор узла,
поэтому разные версии одного имени не смешиваются. Это граф метаданных,
а не полная замена решателю pip: глобальный подбор единой версии с откатом,
выбор wheel по платформенным тегам и установка пакетов не выполняются.

## Этап 4

`order.loading_order` и вложенная `visit` выполняют рекурсивный DFS
с добавлением пакета после его зависимостей. Повторения исключаются.
При цикле выводится ошибка с маршрутом: корректного порядка не существует.
Корневой пакет выводится последним; для листа порядок содержит только его.
На этапе 4 CLI печатает этот порядок, а не визуализацию.

Фактическое сравнение с pip для трёх пакетов, объяснение расхождений
и демонстрации тестовых случаев приведены в [docs/comparison.md](docs/comparison.md).
Pip использован только для независимого эталона, не внутри приложения.

## Этап 5 — итоговая версия

Обычный запуск выводит описание графа на языке Graphviz DOT. При
`ascii_tree = true` после пустой строки выводится ASCII-дерево.
Параметры этапа 1, прямые зависимости этапа 2 и порядок этапа 4
в итоговом CLI отдельно не печатаются: в задании это временные режимы.

```sh
./run.sh examples/diamond.toml
./run.sh examples/cycle.toml
./run.sh examples/local-requests.toml
./run.sh examples/local-python-dateutil.toml
./run.sh examples/local-packaging.toml
```

Для трёх последних команд сначала нужен локальный HTTP-сервер из раздела
«Этап 2». Публичные аналоги: `examples/requests.toml`,
`examples/python-dateutil.toml`, `examples/packaging.toml`.
Они требуют интернета и наличия указанного релиза в выбранном репозитории.

У ASCII-дерева `[cycle]` обозначает обратное ребро к предку,
`[shared]` — повторное использование уже раскрытого узла.
В DOT все рёбра остаются на месте, включая циклы и общие зависимости.
Кавычки в идентификаторах экранируются.

Чтобы перенаправить только корректный DOT в файл, задайте в TOML
`ascii_tree = false` и используйте перенаправление стандартного вывода.
Изображения PNG/SVG и имя файла изображения не добавлены: вариант 6
требует только вывести текст Graphviz, а не сохранить изображение.
Graphviz для запуска приложения не нужен.

Дополнительные функции итоговой версии:

- `versions.prerelease_key`: порядок dev, prerelease и final.
- `repository.is_stable`, `candidate_versions`: отбор релизов.
- `visualization.to_dot`: текстовое описание Graphviz.
- `visualization.to_ascii`, вложенная `visit`: ASCII с метками повторений.
- `__main__.execute`: итоговый вывод DOT и необязательного ASCII.
- `__main__.main`: путь к TOML, запуск и обработка ошибок.

Демонстрации для трёх пакетов, штатный `pip inspect`, эталонный порядок pip
и объяснение различий — в [docs/comparison.md](docs/comparison.md).
Функции тестов документированы docstring; тесты покрывают конфигурацию,
метаданные, версии, маркеры, HTTP, граф, порядок, визуализацию и CLI.

## История этапов и публикация

Каждый этап находится в отдельном Conventional/Scoped Commit
`feat(scope): ...` с подробным сообщением и отмечен тегом `stage-1` … `stage-5`.
Временные режимы можно запускать в соответствующем состоянии истории:

```sh
git switch --detach stage-1
./run.sh examples/requests.toml
git switch main
```

На `stage-2` выводятся прямые зависимости; на `stage-3` — списки смежности;
на `stage-4` — порядок загрузки; на `stage-5` — DOT и опционально ASCII.
Не нужно добавлять в итоговую конфигурацию не предусмотренный вариантами
параметр выбора этапа.

Репозиторий подготовлен локально, но **ещё не опубликован**.
Для выполнения требования о публичной доступности создайте пустой публичный
репозиторий на одном из git-сервисов, перечисленных в задании, и выполните:

```sh
git remote add origin URL_ПУБЛИЧНОГО_РЕПОЗИТОРИЯ
git push -u origin main
git push origin --tags
```

При передаче проекта сохраняйте скрытый каталог `.git`, иначе потеряется
обязательная история пяти этапов. Очная защита этапов выполняется студентом.

[Проверка требований и результаты тестов](docs/verification.md).
[Демонстрации временных режимов этапов](docs/demonstrations.md).
